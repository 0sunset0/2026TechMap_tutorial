# SPEC — AR 도미노 체인리액션 (Day 7 캡스톤)

상태: **핵심 기능 완료** — M1~M4 전부 실기 확인 완료. M5(스트레치)는 스킵. 남은 건 세부 튜닝(임펄스 세기/질량 등)뿐

## 1. 개요

공간에 도미노를 여러 개 세워 배치하고, 첫 도미노를 건드리면 물리 시뮬레이션으로 옆 도미노를 연쇄적으로 쓰러뜨리는 AR 토이. `SpatialCampApp/`과는 별개의 새 Xcode 프로젝트(`ARDominoChainReaction/`)로 만들되, **Day 2~6에서 만든 코드를 옮겨오지 않고 처음부터 새로 작성한다.** (세션 설정, 평면 감지, raycast, 물리 바닥 같은 "익숙한" 부분도 포팅이 아니라 이 프로젝트 안에서 직접 다시 작성하며 복습함 — 현재 M1~M3까지 이 방식으로 완료됨.)

## 2. 목표 (Goals)

- 실제 감지된 평면(바닥/책상) 위에 도미노를 여러 개 세울 수 있다.
- 도미노끼리 서로 충분히 가까우면, 하나를 쓰러뜨렸을 때 물리적으로 옆 도미노에 부딪혀 연쇄적으로 넘어간다.
- 별도의 "쓰러뜨리기 버튼" 없이, 직접 만지는 상호작용으로 체인리액션을 시작한다.

## 3. 범위 밖 (Non-goals) — 이번 버전에서 안 함

- 곡선/분기 경로 도미노 배치 (직선 나열만 지원)
- 정밀한 도미노 간격 자동 계산·정렬 (사용자가 탭한 위치 그대로 배치, 너무 멀면 안 넘어갈 수 있음을 인지하고 진행)
- 리셋/되돌리기 기능, 점수·타이머 등 게임화 요소
- 여러 줄(팀) 동시 배치, 저장/불러오기

## 4. 필수 체크리스트 매핑

| 체크리스트 항목 | 이 프로젝트에서의 구현 |
|---|---|
| 평면 감지 + 앵커 | 이 프로젝트에서 새로 작성하는 `raycastResult` + `AnchorEntity(world:)`로 도미노 배치 |
| RealityKit 엔티티 배치 | 각 도미노 = 얇고 세워진 `ModelEntity`(box mesh) |
| 제스처 상호작용 1개 이상 | 탭으로 도미노 배치 + 드래그로 도미노를 밀어 체인리액션 시작 (배치는 탭, 쓰러뜨리기는 드래그로 서로 다른 제스처를 사용) |

## 5. 사용자 흐름 (User Flow)

```
1. 앱 실행 → 평면 감지될 때까지 대기
2. 평면의 빈 공간을 연속으로 탭 → 도미노가 한 줄로 세워짐 (탭할 때마다 1개씩)
3. 이미 세워진 도미노 중 하나를 손가락으로 드래그(슥 밀기) → 드래그 방향으로 그 도미노가 밀려 넘어짐
4. 물리 시뮬레이션이 연쇄 충돌을 계산 → 옆 도미노들이 순차적으로 쓰러짐
5. 상태 배너가 각 단계마다 무엇을 하면 되는지 안내
```

### ✅ 결정됨 ① — 도미노 배치 방식

**탭으로 한 개씩 배치.** `handleTap`/`raycastResult`로 탭할 때마다 도미노가 하나씩 세워짐. (드래그로 선을 그어 한 번에 배치하는 방식은 M5 스트레치 목표였으나 스킵하기로 결정.)

### ✅ 결정됨 ② — 체인리액션 트리거 방식

**드래그로 밀어서 넘어뜨림.** 손가락으로 도미노를 슥 미는 제스처가 탭보다 직관적이라 이 방식으로 확정.

| 단계 | 내용 |
|---|---|
| 1. 드래그 시작 (`.began`) | 터치 지점에 `arView.entity(at: location)`로 히트 테스트 → 도미노 위에서 시작한 드래그인지 확인, 맞으면 그 도미노를 기억 |
| 2. 드래그 종료 (`.ended`) | 시작점→끝점의 화면상 2D 벡터(`screenDelta`)를 계산 |
| 3. 2D → 3D 변환 | 카메라의 "오른쪽"·"정면" 벡터를 바닥 평면(XZ)에 투영해서 `screenDelta`를 수평 방향 벡터로 매핑 |
| 4. 힘 가하기 | 정규화한 방향으로 `applyLinearImpulse` |

**결정됨**: 임펄스는 드래그 중 실시간이 아니라 **드래그 종료(.ended) 시점에 한 번만** 줌 (더 단순하고 예측 가능해서).

## 6. 기술 설계

캠프 동안 써온 역할 분리 컨벤션(`ARViewContainer.swift` = 설정, `ARCoordinator.swift` = 이벤트 반응)은 검증된 패턴이라 계속 따르지만, **코드 자체는 이 프로젝트 안에서 처음부터 새로 작성했다.**

**현재 상태 (M1~M3 완료)**:

| 파일 | 구현된 내용 |
|---|---|
| `ARDominoChainReactionApp.swift` | 앱 진입점(`@main`) |
| `ARStatusModel.swift` | 화면 상단 배너에 쓸 상태 텍스트(`@Published var statusText`) |
| `ContentView.swift` | `ARViewContainer` + 상태 배너를 겹쳐서 보여주는 SwiftUI 뷰 |
| `ARViewContainer.swift` | `makeSessionConfiguration()`(평면 감지 + People Occlusion) + `configureDebugOptions(for:)` + `setupTapGesture(on:coordinator:)` + `setupPanGesture(on:coordinator:)` |
| `ARCoordinator.swift` | `session(_:didAdd:)`(평면 감지 시 물리 바닥 생성) + `session(_:didUpdate:)`(평면이 넓어질 때 물리 바닥 갱신) + `addPhysicsFloor(for:)` + `raycastResult(for:in:)` + `handleTap`(도미노 배치) + `makeDominoEntity()`/`place(_:at:in:)` + `handlePan(_:)`(드래그로 넘어뜨리기) + `pushDirection(forScreenDelta:in:)` |

**M4 완료 (실기 확인 완료)**: 드래그로 도미노를 밀어 넘어뜨리는 기능과 체인리액션 확인됨.

**밀기 느낌 튜닝 (실기 테스트하며 반복 조정)**:
- `dominoPushStrength`(임펄스 세기): 1.5 → 4.0 → 5.0 → **3.0**(최종)
- 도미노 질량: 한때 `PhysicsMassProperties(mass: 0.05)`(50g)로 직접 가볍게 지정해봤지만, 이후 **`.default`(자동 계산)로 되돌림** — 최종적으로는 임펄스 세기(`dominoPushStrength`)만으로 튜닝

**M4 이후 추가 요청으로 반영한 것**:
- People Occlusion: `makeSessionConfiguration()`에 `frameSemantics.insert(.personSegmentationWithDepth)` 추가 (기기 지원 여부 확인 후 켬). 원래 계획에는 없었지만 사용자 요청으로 추가. 실기 확인 완료.

**아직 안 만듦 (M5 스트레치)**: 드래그로 한 번에 줄 배치

**구현 중 발견한 버그와 수정 (M3 실기 테스트에서 발견)**: 물리 바닥이 실제 평면과 어긋나거나, 평면이 넓어진 뒤 새 영역에서 도미노가 떨어지는 문제가 있었음. 원인은 (1) `ARPlaneAnchor`의 좌표 원점과 실제 평면 중심 사이의 오프셋(`planeAnchor.center`)을 반영하지 않음 (2) 물리 바닥 크기를 평면 감지 시점에 한 번만 고정하고 이후 평면이 넓어지는 걸 반영하지 않음. `floor.position = planeAnchor.center`를 적용하고, `session(_:didUpdate:)`에서 평면 identifier별로 물리 바닥의 위치/크기를 갱신하는 방식으로 해결함 (`physicsFloors: [UUID: Entity]`로 매핑 추적). 참고로 ARKit이 인접 평면을 병합(`didRemove`)하는 경우 물리 바닥이 사라지는 엣지 케이스는 아직 미해결.

### 도미노 엔티티 설계

| 속성 | 값(안) | 비고 |
|---|---|---|
| mesh | `generateBox(width: 0.08, height: 0.2, depth: 0.04)` | 얇고 세워진 직육면체 |
| 재질 | `PhysicallyBasedMaterial`, `baseColor = .red` | 빨간색으로 확정 |
| CollisionComponent | `generateCollisionShapes(recursive: true)` | 도미노끼리 부딪히려면 필요 |
| PhysicsBodyComponent | `.dynamic`, `massProperties: .default` | 실제로 쓰러지고 옆 도미노를 밀어야 함. 질량은 도미노 부피 기준으로 RealityKit이 자동 계산(정확한 값은 미확인 — 대략 0.6kg 안팎으로 추정) |
| 세우는 방법 | 회전 불필요 — `generateBox`의 "높이" 축은 로컬 Y축이고, 평면 raycast의 `worldTransform`도 Y축이 평면 법선과 일치하므로 회전 없이 그대로 두면 세워진 상태가 됨. 다만 mesh가 원점 중심이라 높이의 절반(0.1)만큼 로컬 Y로 띄워야 바닥에 안 파묻힘 |

## 7. 마일스톤 (작은 단위로 빌드 확인하며 진행)

1. **M1 — AR 뼈대** ✅: 앱 진입점 + 상태 배너 + ARSession(평면 감지) 설정 + 평면 감지 시 물리 바닥 생성 + 탭 raycast까지, 아직 도미노는 없는 최소 뼈대 — 실기 확인 완료
2. **M2 — 도미노 하나 세우기** ✅: 탭 → 도미노 1개가 세워진 채로 배치되고, 물리 바닥 위에 서 있음 (쓰러지지 않고 균형 잡힘 확인) — 실기 확인 완료, 빨간색/8×20×4cm로 조정
3. **M3 — 여러 개 줄세우기** ✅: 연속 탭으로 여러 도미노를 한 줄로 배치 — 실기 확인 완료 (물리 바닥 버그 수정 포함)
4. **M4 — 체인리액션** ✅: 도미노 하나를 드래그로 밀기 → 밀려 넘어짐 → 옆 도미노로 연쇄 전파 — 실기 확인 완료 (People Occlusion도 이 단계에서 함께 추가, 임펄스 세기/질량은 이후 계속 튜닝)
5. **M5 (스트레치)** — 드래그로 한 번에 줄 배치 — **스킵하기로 결정** (필수 체크리스트는 M1~M4로 이미 충족됨)

각 마일스톤마다: 코드 작성 → `xcodebuild` 컴파일 확인 → **실기 빌드·실행으로 실제 확인** → 다음 마일스톤.

## 8. 수용 기준 (Acceptance Criteria)

- [x] 평면 감지 후 탭하면 도미노가 세워진 채로 배치된다 (누워있지 않음)
- [x] 도미노 3개 이상을 적당한 간격으로 배치할 수 있다
- [x] 도미노 하나를 드래그로 밀면 넘어지고, 최소 1개 이상의 옆 도미노가 연쇄적으로 넘어간다
- [x] 화면 상단 배너가 각 단계(배치 중 / 배치 완료 / 넘어짐)를 안내한다
